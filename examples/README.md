# Пример результата

Каталог сгенерирован командой (ничего не редактировалось руками):

```
python -m siggen gen \
  --log samples/positive.log \
  --negative samples/negative.log \
  --out out --registry registry/rules.json
```

и скопирован сюда целиком, чтобы было видно, что именно получается на выходе.

| Файл | Что содержит |
|---|---|
| `candidate.json` | ответ модели, прошедший схему. Идентификатора правила здесь нет: ID выделяет `siggen` |
| `decoder.xml` | декодер, собранный из кандидата |
| `rule.xml` | правило, собранное из кандидата |
| `local_rules.xml` | готовый фрагмент для `local_rules.xml` (декодер + правило в `<group>`) |
| `positive.log` | фикстура, на которой правило обязано сработать |
| `negative.log` | фикстура-шум, на которой правило срабатывать не должно |
| `provenance.json` | кто/чем/на основании чего: провайдер, модель, версия и хэш промпта, строка лога |
| `validation.json` | вердикт по каждой проверке и статус прогона через движок |
| `report.md` | отчёт для ревьюера |

Обратите внимание на `validation.json` и `report.md`: там честно записано
`engine_status: skipped` — движок `wazuh-logtest` не был доступен, поэтому
правило **не проверено на реальном движке**. Для вердикта «проверено»
поднимите лабораторию из `docker-compose.yml`.

Соответствующая запись в `registry/rules.json` создана тем же прогоном:
идентификатор `100100` закреплён за детекцией.
